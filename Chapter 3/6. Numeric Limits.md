# `std::numeric_limits<T>` and Floating-Point Numbers

`std::numeric_limits<T>` tells you the properties of a numeric type on your platform, including the smallest and largest values it can hold.

> **Note:** The correct name is `std::numeric_limits<T>`, not `std::number_limits<T>`.

It is defined in the `<limits>` header:

```cpp
#include <limits>
```

## 1. `min()`, `max()` and `lowest()`

```cpp
std::numeric_limits<T>::min()
std::numeric_limits<T>::max()
std::numeric_limits<T>::lowest()
```

| Function | Meaning for `float` / `double` |
|---|---|
| `max()` | The largest finite positive value |
| `lowest()` | The most negative finite value (equal to `-max()` for floating-point types) |
| `min()` | The **smallest positive normalized** value (closest to zero), **not** the most negative value |

### `min()` behaves differently for floating-point types

| Type kind | What `min()` returns |
|---|---|
| Integer (`int`) | The most negative number (`-2147483648` for a 32-bit `int`) |
| Floating-point (`float`, `double`) | A tiny positive number just above zero |

### Number line

```text
lowest()                      -min()   0   +min()                     max()
   |------- negative numbers -----|-----|-----|------ positive numbers ------|
 -3.4e+38                      -1.2e-38     1.2e-38                     3.4e+38     (float)
```

Numbers closer to zero than `min()` are not simply lost. They are stored as **subnormal (denormal)** values, which have reduced precision. The smallest of these is `std::numeric_limits<T>::denorm_min()`.

## 2. Example

```cpp
#include <iostream>
#include <iomanip>
#include <limits>

int main()
{
    std::cout << std::scientific
              << std::setprecision(std::numeric_limits<float>::max_digits10 - 1);

    std::cout << "float min    : " << std::numeric_limits<float>::min()    << "\n";
    std::cout << "float max    : " << std::numeric_limits<float>::max()    << "\n";
    std::cout << "float lowest : " << std::numeric_limits<float>::lowest() << "\n\n";

    std::cout << std::setprecision(std::numeric_limits<double>::max_digits10 - 1);

    std::cout << "double min   : " << std::numeric_limits<double>::min()    << "\n";
    std::cout << "double max   : " << std::numeric_limits<double>::max()    << "\n";
    std::cout << "double lowest: " << std::numeric_limits<double>::lowest() << "\n";

    return 0;
}
```

**Output** (typical IEEE 754 platform)

```text
float min    : 1.17549435e-38
float max    : 3.40282347e+38
float lowest : -3.40282347e+38

double min   : 2.2250738585072014e-308
double max   : 1.7976931348623157e+308
double lowest: -1.7976931348623157e+308
```

Here:

- `std::scientific` is used because these values are too large or too small for fixed notation to be readable.
- `max_digits10` is the number of significant digits needed to print a value so that it reads back as exactly the same number.
- With `std::scientific`, `std::setprecision(n)` counts digits after the decimal point, so we subtract 1.

## 3. Common Pitfall

Using `min()` as the starting value when searching for the largest number in a list of floating-point values is a bug.

```cpp
// Wrong: min() is a tiny positive number, so all-negative data is never beaten
double largest = std::numeric_limits<double>::min();

// Right
double largest = std::numeric_limits<double>::lowest();
```

`lowest()` was added in C++11 for this reason. It works correctly for every arithmetic type, so it is the safe choice when you want "the smallest possible value" generically.

## 4. Related Members

| Member | Meaning |
|---|---|
| `epsilon()` | Gap between `1.0` and the next representable value (about `1.19e-07` for `float`, `2.22e-16` for `double`) |
| `denorm_min()` | Smallest positive subnormal value |
| `infinity()` | Positive infinity (check `has_infinity` first) |
| `quiet_NaN()` | A quiet NaN value |
| `digits10` | Decimal digits that always survive a round trip through the type |
| `max_digits10` | Decimal digits needed to print a value so it reads back exactly |

## Note

- The header is `<limits>`, and the name is `std::numeric_limits<T>`.
- `max()` is the largest finite value, and `lowest()` is the most negative finite value.
- For floating-point types, `min()` is the smallest positive normalized value, not the most negative one.
- Use `lowest()` as the starting value when searching for a maximum.
- Going beyond `max()` in an operation gives `inf`, not wraparound like integer overflow.
- Use `std::scientific` when printing very large or very small floating-point limits.
