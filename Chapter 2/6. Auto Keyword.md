## `auto`

`auto` tells the compiler to **deduce the type** from the value used to initialize the variable.

```cpp
auto a = 10;      // int
auto b = 3.14;    // double
auto c = 'h';     // char
auto d = true;    // bool
```

- The type is decided **at compile time**, so it is still fixed and statically typed
- `auto` is not like a dynamic type in Python or JavaScript. `a` stays an `int` forever
- It is just a shortcut so you don't have to write the type yourself

## A variable using `auto` must be initialized

The compiler needs a value to deduce the type from.

```cpp
auto x;        // error: nothing to deduce the type from
auto y = 5;    // OK: int
```

## Types of common literals

| Literal   | Deduced type   |
|-----------|----------------|
| `42`      | `int`          |
| `42L`     | `long`         |
| `3.14`    | `double`       |
| `3.14f`   | `float`        |
| `'h'`     | `char`         |
| `true`    | `bool`         |
| `"hello"` | `const char*`  |

> `auto s = "hello";` gives a `const char*`, **not** a `std::string`.
> To get a `std::string`, write `auto s = std::string("hello");` or use the `s` suffix: `"hello"s`.

## Linking back to `char`

Arithmetic on a `char` produces an `int`, and `auto` follows that:

```cpp
char c = 'A';

auto d = c;        // char  (copy of c)
auto e = c + 1;    // int   (c is promoted to int)
auto f = (char)(c + 1);  // char ('B')
```

This is the same promotion rule from earlier, so `e` holds `66`, not `'B'`.

## Integer division

`auto` doesn't change how the math works. It only picks the type of the result.

```cpp
auto x = 5 / 2;      // int, value 2
auto y = 5 / 2.0;    // double, value 2.5
```

## `auto` with `const` and references

Plain `auto` makes a **copy** and drops `const` and `&`.

```cpp
int n = 10;
const int& ref = n;

auto a = ref;          // int (copy, const and & dropped)
const auto& b = ref;   // const int& (no copy, read only)
auto& c = n;           // int& (alias of n)
```

| Declaration     | Meaning                          |
|-----------------|----------------------------------|
| `auto x`        | copy                             |
| `auto& x`       | reference (can modify original)  |
| `const auto& x` | read-only reference (no copy)    |

## Where `auto` is really useful

Long type names:

```cpp
std::vector<int> v = {1, 2, 3};

std::vector<int>::iterator it1 = v.begin();  // without auto
auto it2 = v.begin();                        // with auto
```

Range-based `for` loops:

```cpp
for (auto x : v)        { }   // copy of each element
for (auto& x : v)       { }   // modify elements
for (const auto& x : v) { }   // read only, no copy (preferred for big types)
```

Function return types (C++14 and later):

```cpp
auto add(int a, int b) {
    return a + b;   // deduced as int
}
```

## When not to use `auto`

- When the type isn't obvious and it hurts readability
- When you want a specific type different from the value:

```cpp
auto x = 5;          // int
unsigned char y = 5; // if you need exactly this type, write it
```

## Summary

- `auto` = the compiler deduces the type from the initializer
- Must be initialized, and the type is fixed at compile time
- Drops `const` and `&` unless you write `const auto&` or `auto&`
- Best for long type names and loops, less useful for simple types like `int` and `char`
