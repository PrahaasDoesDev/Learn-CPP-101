# Fractional Numbers

- Fractional numbers are also called floating point numbers
- In technical terms, floating point numbers are used to represent numbers with fractional parts in C++

```cpp
3.14
-0.5
2.0
```

## the three types

| type | size | precision | comment |
|---|---|---|---|
| `float` | 4 bytes | 7 digits | - |
| `double` | 8 bytes | 15 digits | recommended default |
| `long double` | 12 bytes | more than double | - |

- **size**: how much memory it takes
- **precision**: how many digits it keeps accurate (counted from the first non-zero digit, not just after the decimal point)
- more bytes = more precision, but more memory
- `long double` size depends on the compiler: 8, 12 or 16 bytes. only guaranteed to be at least as good as `double`

## float

- smallest, 4 bytes, about 7 accurate digits
- fine when precision doesn't matter much or when saving memory (graphics, big arrays)

```cpp
float f {3.14f};
```

## double

- 8 bytes, about 15 accurate digits
- the default for decimal numbers in C++, use this unless you have a reason not to

```cpp
double d {3.14159265358979};
```

## long double

- most precise, but slower and uses more memory
- rarely needed

```cpp
long double ld {3.14159265358979323846L};
```


## literal suffixes

a plain decimal number like `3.14` is a `double` by default. add a suffix to change that:

| written | type |
|---|---|
| `3.14` | `double` |
| `3.14f` | `float` |
| `3.14L` | `long double` |

## scientific notation

for really big or really small numbers, use `e`

```cpp
double big {1.5e6};      // 1.5 x 10^6  = 1500000
double small {2.5e-3};   // 2.5 x 10^-3 = 0.0025
```

## precision loss

only the first few digits are reliable, the rest is rounding noise

```cpp
#include <iostream>
#include <iomanip>

int main() {
    float f {3.14159265358979f};
    double d {3.14159265358979};

    std::cout << std::setprecision(15);
    std::cout << f << "\n";   // 3.14159274101257  (only ~7 digits are right)
    std::cout << d << "\n";   // 3.14159265358979  (~15 digits are right)
}
```
> **Note:** `<iomanip>` is a C++ header that provides "manipulators" for formatting input and output streams like `cout`, such as `std::setprecision` (digits shown), `std::setw` (field width), `std::setfill` (padding character), and `std::fixed` (fixed decimal notation, although this one is actually in `<ios>`). You use them by streaming them into `cout`, like `std::cout << std::setprecision(3) << 3.14159;`, which prints `3.14`.

- `cout` prints only 6 digits by default, use `std::setprecision(n)` to see more

## not exact

computers store these in binary, so many decimals can't be stored perfectly

```cpp
std::cout << std::setprecision(17) << (0.1 + 0.2);   // 0.30000000000000004
```
We use `std::setprecision(precisionValue)` to set the precision limit, it controls the precision from std::cout

- never compare floating point numbers with `==`
- compare with a small tolerance instead

```cpp
#include <cmath>

if (std::abs(a - b) < 1e-9) {
    // treat as equal
}
```
> **Note:** `<cmath>` is a C++ header that provides common math functions like `std::sqrt`, `std::pow`, `std::abs`, `std::sin`, `std::floor`, and `std::round`, mostly working on `double`, `float`, and `long double`. You include it and call them directly, like `std::sqrt(16.0)`, which gives `4.0`.

## integer vs fractional division

```cpp
5 / 2      // 2    (both are int, decimal part is dropped)
5.0 / 2    // 2.5  (one side is double, so result is double)
```

## check on your machine

```cpp
#include <iostream>

int main() {
    std::cout << sizeof(float) << "\n";         // 4
    std::cout << sizeof(double) << "\n";        // 8
    std::cout << sizeof(long double) << "\n";   // 8, 12 or 16
}
```

## what to use

- normal decimals: `double`
- tight on memory, low precision is okay: `float`
- need extra precision: `long double`
- money: don't use floating point, store it as an integer (cents) instead


# How floating point numbers are stored in memory

- stored like scientific notation, but in binary
- the standard is IEEE 754

## the formula

```
value = (-1)^sign × 1.mantissa × 2^(exponent - bias)
```

- **sign**: 0 = positive, 1 = negative
- **mantissa** (significand / fraction): the digits of the number
- **exponent**: the power of 2, moves the point left or right
- **base**: always 2, built into the format so it's not stored
- **bias**: a fixed number added to the exponent so it can be stored without a sign bit

## bit layout

| type | total | sign | exponent | mantissa | bias |
|---|---|---|---|---|---|
| `float` | 32 bits | 1 | 8 | 23 | 127 |
| `double` | 64 bits | 1 | 11 | 52 | 1023 |

```
float:  [ 1 ][   8 bits   ][        23 bits         ]
         sign   exponent            mantissa
```

## example: 5.75 as a float

1. to binary: `5` = `101`, `.75` = `.11`, so `5.75` = `101.11`
2. move the point so there is one digit before it: `1.0111 × 2^2`
3. fill the fields:
   - sign = `0` (positive)
   - exponent = `2 + 127 = 129` = `10000001`
   - mantissa = digits after the point (`0111`), padded with zeros to 23 bits

```
0 | 10000001 | 01110000000000000000000
```

reading it back: `1.0111` (binary) = `1.4375`, and `1.4375 × 2^2 = 5.75`

## things to know

- **leading 1 isn't stored**: every number starts with `1.` in this form, so only the digits after it are saved. free extra bit, so float has 24 bits of precision, double has 53
- **precision comes from the mantissa**: 24 bits is about 7 decimal digits, 53 bits is about 15-16 (matches the table in the slide)
- **bias handles negative exponents**: the exponent field is unsigned, `127` means 2^0, `126` means 2^-1 and so on. that's how small numbers like `0.001` are stored
- **range comes from the exponent**: float goes up to about `3.4 × 10^38`, double up to about `1.8 × 10^308`
- **special patterns**: exponent all zeros = zero (or tiny numbers), exponent all ones = infinity or NaN

## summary

| part | controls |
|---|---|
| sign | positive or negative |
| exponent | how big or small (range) |
| mantissa | how accurate (precision) |

## why 0.1 isn't exact

- in binary, `0.1` = `0.0001100110011...` repeating forever, like 1/3 in decimal
- mantissa only has 23 or 52 bits, so it gets cut off
- you store a very close value, not the exact one
- that's why `0.1 + 0.2` isn't exactly `0.3`

## reference

- this layout comes from the IEEE 754 standard (float = binary32, double = binary64)
- more details: https://en.wikipedia.org/wiki/IEEE_754


# Note:

There are a few things you can do with floating point numbers which you can't do with normal integers
- You can divide with zero, when you divide with zero you get infinity, when you divide a positive number with zero you get positive infinity and when you divide a negative number with infinity you get negative infinity.

- If you take 0.0 and divide it with 0.0, i.e: 0.0/0.0 you will get the output: NaN which stands for Not an Number
- Remember the suffixes when initializing floating point variables, otherwise the default will be double 
- Double works well in many situations, so you will see it used a lot
